Git 仓库

克隆到工作区

克隆后可直接用在线 IDE 打开
凭据安全：本次填写的账号密码 / Token 只在 git clone 进程参数里出现，通过临时 http.extraHeader 传递，不会写入 .git/config、不会落到工作区、也不会保存进 state.json；失败日志会自动脱敏。SSH 地址（git@ / ssh://）走本机 SSH 密钥，账号密码无效。

Git 仓库

登记外部 Git 源

GitHub / 自建 Gitea / GitLab
平台自带 Gitea 已内置；登记外部源后，仓库列表会一并聚合，可直接克隆到工作区并用在线 IDE 开发。支持 Token 与账号密码两种认证方式。
Token 方式：GitHub 用 Bearer、GitLab 用 PRIVATE-TOKEN、Gitea 用 token 头，权限最完整。
账号密码方式：统一走 HTTP Basic 调用 REST API 与克隆；自建 Gitea / GitLab 可直接填账号密码，GitHub 请在密码栏填 PAT（GitHub 自 2021 起停用密码认证）。
凭据只写入本机 data/state.json（600 权限），列表接口一律脱敏；登记后点「测试连通」验证。

全局代理

检测中…
留空 = 继续向下继承；direct = 明确直连并清除子进程继承的代理变量。URL 中的账号密码只存 state.json，界面一律显示 ******。

分组代理

留空继承全局代理
四类对象各自一条分组规则：Git 仓库 / Docker 容器 / 服务器 SSH / AI 服务。分组代理优先于全局代理、低于单项覆盖与 Git Host 规则；填 direct 可让整组强制直连。

Git Host 匹配规则

单个仓库代理之后、Git 分组代理之前生效
按仓库地址的主机名匹配，支持精确值（github.com）与通配符（*.gitea.internal）；多条规则按添加顺序，先命中先生效。常用来「外网走代理、内网直连」。

单项代理覆盖

仓库 / 容器 / 服务器 / AI 服务，优先级最高
这一栏怎么填
① 作用域：选要为哪一类对象单独指定代理；② 对象：从下拉里选具体仓库 / 容器 / 服务器 / AI 服务（下拉没有时可在「对象标识」里手填 id）；③ 代理地址：填这条对象专属的代理。
可填的值：http://127.0.0.1:7890、http://user:pass@proxy.example.com:8080、https://…、socks5://127.0.0.1:1080（仅 SSH 隧道与本地 CLI 生效）、direct（明确直连，清除子进程继承的代理变量）。留空并点「保存覆盖」= 删除这条覆盖，让对象回到下一级规则。
优先级：单个仓库代理 > Git Host 匹配规则 > Git 分组代理 > 全局代理；单个容器 > Docker 分组 > 全局；单个服务器 > 服务器分组 > 全局；单个 AI 服务 > AI 服务分组 > 全局。命中即停止。
示例：让 github.com 走 http://127.0.0.1:7890、公司内网 Gitea 直连 → 在「Git Host 匹配规则」加 *.gitea.internal → direct；只让某个私有仓库走代理 → 在这里选该仓库并填代理地址。URL 中的账号密码只写 state.json（600 权限），界面一律显示 ******。
