分组代理

留空继承全局代理
四类对象各自一条分组规则：Git 仓库 / Docker 容器 / 服务器 SSH / AI 服务。分组代理优先于全局代理、低于单项覆盖与 Git Host 规则；填 direct 可让整组强制直连。

Git Host 匹配规则

单个仓库代理之后、Git 分组代理之前生效
按仓库地址的主机名匹配，支持精确值（github.com）与通配符（*.gitea.internal）；多条规则按添加顺序，先命中先生效。常用来「外网走代理、内网直连」。

单项代理覆盖

仓库 / 容器 / 服务器 / AI 服务，优先级最高
这一栏怎么填
① 作用域：选要为哪一类对象单独指定代理；② 对象：从下拉里选具体仓库 / 容器 / 服务器 / AI 服务（下拉没有时可在「对象标识」里手填 id）；③ 代理地址：填这条对象专属的代理。
可填的值：http://127.0.0.1:7890、http://user:pass@proxy.example.com:8080、https://…、socks5://127.0.0.1:1080（仅 SSH 隧道与本地 CLI 生效）、direct（明确直连，清除子进程继承的代理变量）。留空并点「保存覆盖」= 删除这条覆盖，让对象回到下一级规则。
优先级：单个仓库代理 > Git Host 匹配规则 > Git 分组代理 > 全局代理；单个容器 > Docker 分组 > 全局；单个服务器 > 服务器分组 > 全局；单个 AI 服务 > AI 服务分组 > 全局。命中即停止。
示例：让 github.com 走 http://127.0.0.1:7890、公司内网 Gitea 直连 → 在「Git Host 匹配规则」加 *.gitea.internal → direct；只让某个私有仓库走代理 → 在这里选该仓库并填代理地址。URL 中的账号密码只写 state.json（600 权限），界面一律显示 ******。

ADMIN_TOKEN 鉴权说明

正在读取状态…
正在读取 .env…
它是什么 / 作用

平台唯一的一把共享密钥（不是账号体系）。启动时读入 config.adminToken，非空时由 mini.js 在 /api/* 入口统一校验，除 /api/health 外所有接口缺令牌一律 401；静态页面文件本身不鉴权。

  • 普通请求：Authorization: Bearer <ADMIN_TOKEN>
  • SSE 终端 / 下载 / 上传链接：?token=<ADMIN_TOKEN>
留空（未配置）的影响
  • 所有 API 完全不鉴权：任何能访问 9000 端口的人都能读配置与连接串、浏览 / 编辑服务器文件、打开 Web 终端、增删容器、触发部署，等同拿到平台管理员权限。
  • 兜底降级：/api/servers/:id/exec 只允许只读白名单命令，写命令返回 403。
  • 只适合可信本机，或已用防火墙限制 9000 端口的内网。
启用步骤
  1. 生成强随机值（可用下方按钮），填入表格中 ADMIN_TOKEN 的「新值」列，点「保存并应用」（自动备份 .env、权限 600）。
  2. 完全重启平台：本机重启 exe；容器部署重跑 remote.js deploy。devplatform.exe reload 只重启业务进程，不会重新读取 .env。
  3. 每台要访问控制台的浏览器按 F12 执行一次 localStorage.setItem('dp_token', '<同一个令牌>') 后刷新；curl / 脚本按上面的 Bearer / ?token= 带令牌。
  4. 更换令牌后旧浏览器会持续 401，需要重新写入 dp_token。
只在表单里生成并填入，不会自动写 .env；保存前请复制该值备用。
局限与注意：单一共享令牌，没有多用户 / 过期 / 权限分级 / 操作审计；明文存于 .env（600）与浏览器 localStorage；?token= 会进入 URL 与访问日志，公网请配 HTTPS。它与 Gitea / OpenList / code-server 各自的登录密码互不相干。完整说明见 .env.example 与 README §5 / §40。

.env 配置文件

只读查看 + 白名单写入，敏感值一律脱敏
正在读取 .env…
文件在哪：容器部署时平台读到的是挂载进容器的 /app/.env，对应宿主机 <部署目录>/.env（例如 /data/platform/.env），权限 600；Windows 单文件版是 exe 同目录下的 .env。
什么时候要重启：标注「需重启」的键在平台启动时读入，写回文件后要重启平台进程 / 容器才生效；容器部署重新执行一次 remote.js deploy 即可。DP_TLS_INSECURE 这类开关标记「即时」，保存后立即生效。
安全边界：只支持下表白名单内的键；写入前自动备份为 .env.bak.<时间戳>；平台不执行 shell、不自动重启、不改 state.json。

仅管理员可进入；普通用户只能看到自己与被授权协作的数据
权限规则：管理员可查看 / 操作所有数据；创建者（owner）对自己的数据全权；协作者分 read（只读）与 write（可操作、不可删除 / 不可改协作者）。全局配置（.env、代理、环境适配、系统更新等）对普通用户只读。
新账号固定为「普通用户」，仅初始管理员拥有管理员权限；密码留空则由系统自动生成。

登记外部 Git 源

GitHub / 自建 Gitea / GitLab
登记外部源后，仓库列表会一并聚合。支持 Token 与账号密码两种认证方式；凭据栏留空表示编辑时沿用原值。自建服务证书过期 / 自签名导致连不上时，可在下方选择忽略 TLS 校验，或到「环境配置」页设置全局开关。
安全提醒：忽略证书校验会失去防中间人攻击能力，只建议用于可信任内网的自建服务临时应急；长期方案是为服务端续期 / 换用受信任证书。该设置同时作用于仓库列表 API 与 git clone（http.sslVerify=false），但不会写进仓库的 .git/config。
全局开关在「环境配置」页：DP_TLS_INSECURE=1，可用 DP_TLS_INSECURE_HOSTS 限定域名。
Token 方式：GitHub 用 Bearer、GitLab 用 PRIVATE-TOKEN、Gitea 用 token 头，权限最完整。
账号密码方式：统一走 HTTP Basic 调用 REST API 与克隆；自建 Gitea / GitLab 可直接填账号密码，GitHub 请在密码栏填 PAT（GitHub 自 2021 起停用密码认证）。
凭据只写入本机 data/state.json（600 权限），列表接口一律脱敏；登记后可点列表里的「测试连通」验证。
编辑已登记的源：名称 / 类型 / 地址 / 认证方式都能改；凭据栏留空表示沿用原值（列表里显示的是脱敏值，不会写回）。
